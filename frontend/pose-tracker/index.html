How it works

The skeleton isn't from a third-party pose library. It's a ResNet18-shaped CNN (~15M parameters, random init — no ImageNet pretraining) with a 3-stage deconvolution head, trained from scratch on COCO 2017 keypoints (tens of thousands of labeled people, 17 joints including face points). It regresses a heatmap per joint; each webcam frame is center-cropped to a square, resized to 256×256, run through the net as ONNX in WebAssembly, and the per-joint peak becomes a keypoint.

Wrists track hand position, shoulders and hips form the torso, and neck/chest are derived as the shoulder midpoint and the neck-to-hip midpoint — COCO has no keypoint for either, so those two are computed client-side, not predicted by the net.

It's honest about its limits: single person, wrist position rather than finger articulation, and still rougher than commercial pose libraries trained on datasets and compute far beyond what this was trained with. Stand centered, mostly full-body, for the best results.

Data
COCO 2017 person_keypoints annotations, filtered to instances with ≥5 labeled joints and a reasonable box size, then cropped per person rather than resizing whole images — one photo with 3 people yields 3 training crops. 124,823 crops came from ~45k images; only the images actually needed were downloaded individually (a few GB), not the full 18GB archive.
Augmentation
Random horizontal flip — with left/right joint labels swapped, since flipping without relabeling teaches the model "left shoulder" means whatever ended up on the right — plus random crop scale/position jitter and brightness/contrast jitter. Training-only.
Targets
Each joint's ground truth is a 64×64 Gaussian heatmap (σ=2), not a raw (x, y) coordinate. Heatmap regression trains far more stably than direct coordinate regression — every nearby pixel gets a gradient instead of only the one exact target pixel.
Model
A ResNet18-shaped backbone (4 residual stages, random init, no ImageNet pretraining) feeding a 3-stage transposed-convolution head that upsamples back to 64×64. 15.4M parameters, every one trained from scratch on this dataset — no pretrained weights anywhere in the pipeline.
Loss & training
Masked MSE between predicted and target heatmaps — joints with no ground truth in a given crop don't contribute to the loss. Adam with a cosine learning-rate schedule; only the best-validation-PCK checkpoint is kept. Reached val PCK@0.2 = 0.93 in 8 epochs (~70 min on an RTX 3060) and was stopped there once gains clearly plateaued, well short of the full 35-epoch schedule.
Export
PyTorch → ONNX via torch.onnx.export, then checked for byte-for-byte parity between ONNX Runtime's output and the original PyTorch model on the same input before shipping it.
Client inference
Runs entirely in your browser via onnxruntime-web: the webcam frame is center-cropped to a square, resized to 256×256, packed into a float32 tensor, and run through the model in WebAssembly with SIMD, single-threaded on the main thread — this model is small enough that the added complexity of a multi-threaded worker pool isn't worth it. Each joint's position is just the argmax pixel of its predicted heatmap.
Derived points
Neck and chest aren't model outputs — COCO has no such keypoints — they're computed client-side as the shoulder midpoint and the neck-to-hip midpoint.
Reproduce it
The exact commands used to prepare the data, train, and export this model — no hidden steps: 
python3 -m venv venv && source venv/bin/activate
pip install torch torchvision onnx onnxruntime scipy numpy pillow huggingface_hub tqdm requests

# annotations + only the images that actually contain labeled people
mkdir -p data/coco && cd data/coco
curl -sL -o annotations.zip http://images.cocodataset.org/annotations/annotations_trainval2017.zip
unzip -o annotations.zip "annotations/person_keypoints_*" && rm annotations.zip
cd ../..
python train/prepare_coco.py

python train/train_coco.py       # 8 epochs run, ~9 min/epoch on an RTX 3060 Laptop GPU
python train/export_onnx_coco.py # writes frontend/pose-tracker/vendor/pose_net.onnx
python train/check_quality.py    # sanity-check grid of predictions vs. ground truth
Full source — data prep, model, training loop, ONNX export, and the per-epoch training log — is in train/ in the repo.

All processing happens locally in your browser. Video is never transmitted or stored.
